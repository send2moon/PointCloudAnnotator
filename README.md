# 作物点云处理软件

面向小麦等作物点云的桌面处理软件，含**器官标注**、**点云裁剪**与**标注核查**三个独立功能页：
浏览、逐点标注穗/叶/茎、按任意形状裁出目标区域、绕轴旋转、调用脚本配准裁剪，
并支持 e57 / PLY / PCD / 文本等多种格式保存，**不丢失坐标、颜色、强度与结构信息**。

> 软件名称：作物点云处理软件（窗口标题、任务栏、对话框标题均显示此名）。
> `PointCloudAnnotator` 只是内部英文标识，用于 QSettings 配置键、程序目录与启动器，
> 保留不改以免丢失上次目录、拾取深度等偏好设置。

### 修改 run.bat 的注意事项

Windows 的 `cmd.exe` 以 **GBK** 读取 `.bat`，并且要求 **CRLF** 行尾。
**不要用 UTF-8 中文注释写批处理**——中文会被解码成乱码行并当作命令执行，
LF 行尾还会让 `if` / `goto` 块解析错乱，两者都会导致"启动失败"。

需要改 run.bat 时请重新生成（自动保证 ASCII + CRLF）：

```bat
python _gen_bat.py
```

因此启动器控制台的 `title` 仍是 ASCII 的 `CropPointCloudAnnotator`；
程序启动后由 `src/app.py` 用 `SetConsoleTitleW` 把控制台标题改成中文软件名。
软件主窗口标题不依赖批处理，始终是中文名。

## 主要功能

### 三个功能页（Office 风格界面）

2.0 起软件拆成两个互不干扰的功能页，顶部蓝色选项卡行切换，下面一行是各自的功能区：

| 页面 | 做什么 | 数据 |
| --- | --- | --- |
| **器官标注** | 穗 / 叶 / 茎语义与实例标注、穗实例分割、修改已有标注 | 读写 `annotationLabel` / `annotationInstance`，不删点 |
| **点云裁剪** | 文件夹列表、矩形 / 任意多边形区域裁剪、绕轴旋转、覆盖或另存、脚本配准裁剪 | 只改几何与文件，不写标注 |
| **标注核查** | Point-SAM 正负点分割、候选预览、补标与类别/实例边界修正 | 独立核查文档，应用后写入标注，不改变点序和几何 |

界面整体改为 **Office 风格**：白底、蓝灰细边框、Word 蓝 `#2b579a` 作唯一强调色、
分组框带蓝色小标题、按钮 hover 才显色，悬浮说明是浅色卡片气泡。
三维视图画布仍可单独选深 / 浅 / 白，因为真彩色点云在深底上对比度更高——
这也和 Office 里嵌入的 3D / 图表视窗一致。样式集中在 `src/office_theme.py`。

两页**各自管理自己的文件、撤销栈与未保存标记**。切换时同名快捷键会隔离：
在裁剪页 `Ctrl+S` 是覆盖保存、`Ctrl+Shift+S` 是另存为；在标注页两者含义相反。
标注页的 `QAction` 切到裁剪页时全部禁用，裁剪页用挂在自身控件上的 `QShortcut`
（`WidgetWithChildrenShortcut`）并随页面启停，不会互相抢事件。

两页的 1920×1080 界面截图见 `outputs/office/ui_annot_page.png` 与
`outputs/office/ui_crop_page.png`，由 `_shot_office.py annot` / `_shot_office.py crop` 分别生成
（蓝色通栏选项卡行、功能区、Office 白底侧栏、裁剪页文件列表与多边形区域均可见）。

### 窗口与布局（启动即最大化）

软件启动后直接**最大化**——标注是"看大图"的活，窗口越宽越容易定位到单株。

* 最小窗口 **1000×640**，再小也不会把控件挤成省略号
* **侧栏宽度自适应**：占窗口宽度约 21%，夹在 320–520 px 之间；
  也可以直接拖分隔条自己定，**拖过之后就不再自动改**（不会被抢回去）
* **侧栏可滚动**：窗口不够高时（如 1366×768 或系统缩放 150%）上半部分出现滚动条，
  而不是把"保存"按钮切掉；**「保存」组固定在侧栏底部**，任何尺寸下都点得到
* 窗口高度 < 1180 px 时自动进入**紧凑模式**：收起两句说明文字、缩小分组间距、
  列表最小高度 180→110；说明内容仍在按钮 tooltip 里
* 按钮宽度按文字实测宽度定下限，侧栏最窄时 `浏览/笔刷/橡皮/框选/实例/裁剪`、
  `语义/实例` 与 `穗/叶/茎/其他` 也都能完整显示（不出现 `浏…`）
* 「扫描 / 实例」列表排在「显示」之前：小屏滚动时先看到标注结果
* 状态栏文件名可被压缩，完整路径在 tooltip 里，不会把右侧的渲染耗时挤出去
* 关闭时记下**非最大化**时的窗口大小，下次启动仍最大化，取消最大化后回到熟悉的大小

不同窗口尺寸下的实测（`_probe_layout.py`）：

| 窗口 | 侧栏宽 | 内容 / 视口高度 | 是否需要滚动 |
| --- | --- | --- | --- |
| 2560×1440 | 520 px（20%） | 948 / 1200 px | 否 |
| 1920×1080 | 403 px（21%） | 829 / 878 px | 否（余 49 px） |
| 1366×768 | 360 px（26%） | 滚动 263 px | 是（上半部分） |
| 1000×640 | 360 px（36%） | 滚动 391 px | 是（上半部分） |

> 1920×1080 这一档是本轮专门优化出来的：新增「语义/实例」切换、两个隐藏开关、
> 「改标注…」按钮之后侧栏一度超出 162 px 出滚动条。三处收口后归零——
> ① 标注方式并入「器官类别」标题行、`改标注…` 并入操作行；
> ② 扫描列表自定义 `sizeHint`（Qt 默认 256 px 是主因）；
> ③ 「着色」与「点大小」并成一行。

### 悬浮说明（鼠标停在按钮上就能看到）

说明通常两三行：第一行是「做什么」，后面是「什么时候用 / 注意什么」。

* 工具按钮（浏览/笔刷/橡皮/框选/实例/裁剪）说明操作方式与撤销粒度
* 类别按钮（穗/叶/茎/其他）说明该类别包含什么、后续能做什么
* 「语义 / 实例」说明两种标注方式的差别；「隐藏已标注 / 隐藏当前类别」说明只影响显示
* 保存类按钮注明「另存」与「覆盖」的区别
* 对话框里的按钮同样有说明（执行裁剪 / 执行分割 / 清空全部 / 取消…）

气泡样式写在 `src/office_theme.py` 的 `OFFICE_QSS` → `QToolTip` 规则里；

### 多站 E57 位姿（重要）

数据集里每个 `<data3D>` 都带一个 `<pose>`（四元数旋转 + 平移），描述"扫描局部坐标 →
文件坐标系"的变换。`pye57` / `libE57` 读出来的原始列是**未变换的局部坐标**，
必须自行套用，CloudCompare 就是这么做的。

若忽略 pose，同一份文件会显示成**散在四周的一圈碎片**（本数据集 16 个站位散成半径 9 m 的环）；
套用后即拼成一个 3.7 × 5.5 × 1.2 m 的完整小区。

软件的默认行为是**按 pose 烘焙坐标**（与 CloudCompare 一致），
左侧「显示 → 应用 E57 位姿（多站拼接）」可关闭以排查位姿问题。
保存时坐标已是统一的全局坐标，写出的 pose 为单位阵，因此在 CloudCompare 里打开不会二次变换。

### 多站扫描需要"先合并"吗？——不需要

e57 本身就是多站容器，软件按 `<data3D>` 逐个扫描写出（例如 12 个站位仍是 12 个
`vectorChild`），**不会合成一个点列**，颜色/强度/标注都按站点各自保留。
"合并"只是视觉上把它们摆到同一个坐标系，有两种等价的保存方式：

| 模式 | 界面开关 | 文件里存什么 | 适用场景 |
| --- | --- | --- | --- |
| 烘焙位姿（默认） | 「应用 E57 位姿」勾上 | 坐标已是全局坐标，pose 写单位阵 | 与 CloudCompare 显示一致，直接量尺寸、裁剪、标注 |
| 保留各站位姿 | 「应用 E57 位姿」取消勾选后**重新打开**文件 | 各站局部坐标 + 原始 `<rotation>/<translation>` | 需要在文件里保留扫描仪位姿元数据、或给下游重建流程用 |

两种文件几何等价：把后者的 pose 套上去，包围盒与前者一致（误差 < 2 mm）。
注意取消勾选后视图会显示成散开的局部坐标，这是正常的；标注仍按点索引进行，存盘不受影响。
已验证 12 扫描 358 万点：12 个 pose 全部原样写回，回读后拼回同一块，各站标注完整。

### 点云裁剪

两种方式，结果一致：

1. **框选裁剪**：左侧「裁剪」工具 → 左键拖出矩形 → 松开后弹出对话框，
   已按框选区域投影出世界坐标范围，可直接微调最小/最大值。
2. **数值裁剪**：工具栏「裁剪…」`C`，直接按 X/Y/Z 包围盒设定范围（默认整个点云）。

对话框内选择语义（单选框是灰描边、选中为 Office 蓝实心，白底上一眼能分清）：

* **保留框内的点**（裁掉框外）——适合从多站拼接结果里截取单株
* **删除框内的点**（保留框外）——适合剔除地面、支架等干扰

裁剪会同步裁剪标注数组，点数变化后实例编号自动清理。
**裁剪是破坏性操作**，可用 `Ctrl+Z` 撤销一次。

> 裁剪时若某个扫描整体落在框外，它会被整段移除（扫描序号前移）。
> 标注数组会同步重建并按掩膜对齐；万一出现错位，标注/保存前会自动对齐并提示。

### 器官标注

* **笔刷**：左键涂抹，右键结束一笔；`[` `]` 调整笔刷大小
* **橡皮**：左键擦除
* **框选**：拖出矩形，松手即整体标注
* **实例**：拖出矩形，把框内**已标为「穗」的点**归为一个新实例编号（手动分穗，见下文）
* 类别：穗 / 叶 / 茎 / 其他

#### 语义标注 vs 实例标注

「器官类别」标题行右侧有 **语义 / 实例** 两个开关（默认实例，选择会记住）：

| 标注方式 | 写入什么 | 适合 |
| --- | --- | --- |
| **语义** | 只写 `annotationLabel`（类别），**不分配实例编号** | 只做「穗/叶/茎/其他」的像素级分类；修正导入文件里标错的类别；先粗标类别，之后再用「穗实例分割」统一编号 |
| **实例** | 类别 + 每次落笔在单个扫描内生成一个**实例编号** | 数穗、数叶；右侧列表按 `类别 #编号 (点数)` 逐条列出 |

* 语义标注的点在右侧列表汇总成一行：`未分实例：穗 1,234 点 / 叶 567 点`；
  没有编号不影响自动分穗（分穗只认类别）、不影响存盘（`annotationInstance` 写 0）。
* 用语义方式覆盖一段**已有实例编号**的点时，这些点的编号会被清掉（该实例仍然存在，
  只是少了这些点）；按 `Ctrl+Z` 可整步退回。
* **当前选中项一定看得出来**：工具按钮选中为蓝底白描边加粗，类别按钮选中后整块填充
  该类别的颜色（穗红 / 叶绿 / 茎蓝 / 其他黄）并描白边，鼠标悬停也能看到

### 隐藏点云：只处理剩下的点

「显示」组里有两个开关，都**只影响显示与拾取，不改标注、不影响存盘**：

* **隐藏已标注** —— 把已经有类别的点全藏起来，只剩未标注的点。
  标完一片就勾上，接着标剩下的植株，不会互相遮挡；新标的点会立刻消失。
* **隐藏当前类别** —— 只藏当前选中类别（例如「穗」），叶/茎/其他照常显示；
  切换类别按钮时，隐藏对象跟着换。

隐藏状态会被记住（换下一个文件仍然生效），看不见的点也点不到、框不到，
所以不会误标；包围盒与「适合窗口」按可见点计算。取消勾选即全部恢复。

### 拾取深度：为什么框选只标到一部分点

框/笔刷先在屏幕上选出候选点，再按**相机深度**筛掉一层——这是"框了一大片却只标到
一部分"的唯一原因，**与多站无关**：多站叠加反而会让同一块区域点更多，标注也是跨站
同时生效的（一次框选可同时写入 8 个扫描，仍只算一个撤销步）。

实测：一个 360×360 像素的框在 94 万点上选中 698,413 个候选点，深度跨度 4.59 m
（从最前排植株一直到背景），四种设置下真正被标注的点数为：

| 侧栏「拾取深度」 | 被标注点数 | 说明 |
| --- | --- | --- |
| 表面层（默认 5 cm） | 13,611 | 只取最前面 5 cm 厚的一层，背面的植株不会被误标 |
| 前 25% | 174,604 | 框内点按深度排序取前 1/4 |
| 前 50% | 349,207 | 取前一半 |
| 全部穿透 | 698,413 | 框内所有点都标注 |

选哪个：

* 标**单个麦穗/叶片** —— 用「表面层」，容差调到比目标器官略厚（麦穗 3–8 cm）；
  框里混进一个孤立的近处噪点也不会把基准带偏（基准取 1% 分位而非最小值）。
* 标**整株/整片** —— 切「全部穿透」，或任何模式下**按住 Ctrl 拖拽**（临时穿透）。
* 相机侧视整行小麦时，"表面"层是一层薄壳；想标整行就加大容差或直接穿透。

状态栏每次标注后会显示 `已标注 N 个点 · 深度 表面 5.0 cm`，点数明显偏少时
先把深度调宽再框一次。

> 另一个容易混淆的点：左侧「显示全部扫描」**取消勾选**时视图里只有当前选中的那一个
> 扫描，框选自然只作用于它。此时状态栏会提示「当前只显示扫描 #k，其余站未参与」。

### 穗实例分割（自动给每一穗编号）

手工一穗一穗地框选太慢，软件提供自动分穗：把**已标为「穗」的点**按空间连通性拆成
一个个独立麦穗，每穗写入一个 `annotationInstance` 编号。

用法：工具栏 **「穗分割…」**（快捷键 `S`）或右侧栏 **「穗实例分割…」**

* **作用范围**：当前扫描 / 全部扫描。**一律逐站分别分割**——每站是同一批植株的
  一次采集，实例编号按站独立，跨站合成一片再分割没有意义。
* **体素边长**：把空间切成小格子，同格与相邻格的点算连通。越小越能把贴在一起的
  相邻穗分开，也越容易把一根穗打碎。经验值 **0.25–0.40 cm**。
* **连通方式**：紧邻（26 邻域，推荐）/ 放宽 2 格（补点云稀疏造成的断口，代价是易粘连）。
* **最小穗点数**：少于这个点数的连通块判为碎片（噪点、断枝），不编号。
* **覆盖已有实例编号**：不勾选 = 只给"还没有编号"的穗点补编号（增量标注）；
  勾选 = 范围内全部重新分割、重新编号（穗点的旧编号一律作废，被判为碎片的点回到"未编号"，
  这样执行结果与试算预览的框数完全一致）。穗点都已有编号时对话框会自动勾上。
* **试算**：不动标注，先看簇数/单穗点数分布，满意再执行。试算会同时在三维视图里
  用**虚线立方体框**把将生成的穗画出来，框顶的 `#319` 就是执行后分配的实例编号，
  参数改一下点一次「试算」即可对比；关闭对话框自动清掉预览框。
* 执行后自动切到「标注」着色并打开「实例框」，右侧列表按 `穗 #编号 (点数)` 逐条列出；
  整次分割只占**一个撤销步**（`Ctrl+Z` 一次全退回），存盘时编号写入 e57。

#### 实例框：把每一穗框出来并标号

「显示」组里的 **实例框** 勾选项（默认关闭）会给**列表聚焦的那一站**中每个已编号的
穗画一个彩色立方体框，框顶小牌显示 `#实例编号`。框用世界坐标轴对齐包围盒，
随相机一起旋转；在左侧列表点别的扫描，框会立刻切到那一站——不同站同时画会叠出
上百个框、编号互相压住，反而看不清。改成多站一起看没有意义，因为实例编号本来就是按站独立编号的。

* 颜色按编号做 HSV 色环打散（`(uid × 47) % 360`），同一编号每次看到的颜色一致。
* 「试算」期间只画虚线的预览框、不画实线框，避免两批框叠在一起。
* 实例框只统计 `annotationLabel == 1`（穗）且 `annotationInstance != 0` 的点，
  因此叶/茎/其他的实例不会被框进穗里。

#### 手动框选穗实例（修正自动分割的结果）

自动分割不可能 100% 正确，贴在一起的两穗会粘连、稀疏的穗会被切断。这时用左侧
**「实例」**工具手工补：

1. 先把这些点标成「穗」（框选/笔刷 + 类别=穗），手动工具**只给穗点发编号**，
   框里的叶/茎/其他点原样不动（状态栏会提示有多少非穗点未参与）。
2. 点「实例」切换到实例工具，**框住一根穗的穗点，松手即成新实例**——
   框顶立刻出现 `#新编号` 的立方体框（会自动勾上「显示 → 实例框」）。
3. 框错按 `Ctrl+Z` 一次退回（一次框选 = 一个撤销步，框跨多站也是整步撤销）。

常见修正方式：

| 目标 | 做法 |
| --- | --- |
| **合并**（自动把一根穗拆成两段） | 把两段一起框住 → 它们归到同一个新编号 |
| **拆分**（自动把两穗粘成一团） | 只框住其中一根 → 它拿到新编号，另一根保持原号 |
| **重编**（编号乱了想重排） | 直接框住目标穗，旧编号自动作废 |

深度筛选与「框选」一致：默认只取表面层（避免框到后面另一株的穗），
按住 `Ctrl` 拖拽临时改为全部穿透；侧栏「拾取深度」也能调。

默认参数（0.30 cm / 26 邻域 / 10 点）在 `1-FS_09_labeled.e57` 上的实测：
扫描 8 的 14,696 个穗点 → **19 个穗**，单穗 60–1700 点，耗时约 10 ms；
同一批参数对扫描 1（318 点）→ 5 个穗。调体素与最小点数的影响：

| 体素 | 最小点数 | 簇数（扫描 8） | 单穗中位点数 | 主轴长中位 | 穗粗中位 |
| --- | --- | --- | --- | --- | --- |
| 0.20 cm | 5 | 55 | 15 | 1.5 cm | 0.3 cm |
| 0.20 cm | 10 | 36 | 54 | 2.7 cm | 0.5 cm |
| 0.25 cm | 10 | 24 | 312 | 4.6 cm | 0.8 cm |
| **0.30 cm** | **10** | **19** | **488** | **4.8 cm** | **0.8 cm** |
| 0.50 cm | 20 | 14 | 851 | 9.8 cm | 1.0 cm |

正常小穗应是"一根细长柱"：长 4–8 cm、粗 1–2 cm、长宽比 5–6。簇数明显偏少、
单穗长度超过 10 cm，说明体素太大把相邻穗连成一片了；簇数暴涨且单穗只有十几点，
说明体素太小把穗打碎了。先「试算」调到接近这个形态再执行。

**已知局限（务必知道）**：田间麦穗常常彼此紧贴甚至交叠，自动分割在紧贴处会粘连、
在点云稀疏处会切碎。本功能的作用是"把 90% 的活一次干完，剩下的手工修"——
分割后用笔刷/框选把漏标的穗换个编号、把粘连的两穗拆开即可。
无法做到 100% 自动的客观原因是数据本身：抽查该文件 43 个手工实例，其中 36 个（84%）
在 0.3 cm 体素下就是**空间不连通**的多块（跨度 12 cm、13 个连通块），也就是说
手工编号本身是按"一片区域"打的，并不能当作逐穗的评判标准。

### 修改已有标注（标注管理）

导入别人标过的文件、或想批量整理自己的标注时，用 **「改标注…」**（侧栏操作行）
或工具栏 **「标注管理…」**（快捷键 `M`）。

对话框按扫描列出文件里**现有**的标注：

```
扫描 1/8    811 点    已标注 811 点
     穗 #45   (5 点)
     穗 #50   (15 点)
     ...
     穗（未分实例）   (1,234 点)
     叶 #12   (300 点)
```

选中一行或多行（`Ctrl` / `Shift` 多选）后可做：

| 操作 | 说明 |
| --- | --- |
| **改类别为…** | 把选中实例/语义组整体改成穗/叶/茎/其他，实例编号保留 |
| **转为语义（去实例号）** | 保留类别、清掉编号，这些点归入「未分实例」一行 |
| **合并为一个实例** | 把选中的多行（含语义组）合成一个新实例，类别取多数；用于把切碎的穗重新合起来 |
| **删除选中点的标注** | 恢复为未标注（类别与编号都清空），需确认 |
| **按类别清除（全部扫描）** | 一次清掉所有「穗」或所有「叶」的标注，含其全部实例，需确认 |
| **清空当前扫描 / 清空全部标注** | 整段清空，需确认 |

* 每个操作都是**一个撤销步**，`Ctrl+Z` 可整步退回（"清空全部 + 撤销"也在测试里验证过编号不会撞号）。
* 操作后标注列表、实例框、隐藏状态、顶部统计同步刷新；可继续在视图里用笔刷/框选微调。
* 导入文件里 `annotationInstance` 缺失（只有类别）时，会显示为「未分实例」行，
  可先用「合并为一个实例」或自动分穗补编号。

### 保存（支持多种点云格式）

* **保存为标注点云…** `Ctrl+S`：另存为新文件，格式由保存对话框里选的**扩展名**决定，
  当前打开的文件不受影响
* **覆盖保存** `Ctrl+Shift+S`：按**原格式**写回当前文件

| 格式 | 打开 | 保存 | 标注存放位置 |
| --- | --- | --- | --- |
| **e57** | ✅ | ✅ | `annotationLabel` / `annotationInstance` 两个原生整型字段 |
| **PLY** | ✅ 二进制 / ASCII | ✅ 二进制小端 | 额外顶点属性 `label`(uchar) / `instance`(ushort) |
| **PCD** | ✅ ascii / binary | ✅ binary | 额外字段 `label`(U1) / `instance`(U2)，`rgb` 按 PCL 约定打包 |
| **CSV** | ✅ | ✅ | 表头带 `label,instance` 两列 |
| **XYZ / TXT** | ✅ | ✅ | 首行 `#` 注释写明列名，逐行 `x y z r g b label instance intensity` |
| **PTS** | ✅（Leica，首行点数） | —（另存时按 xyz 写） | — |

要点：

* **标注跟着几何走**：换格式再打开，类别与实例编号都还在（PLY/PCD 的 label 列在
  CloudCompare 里会显示成标量场，可按它着色筛选）。
* **多站文件**：e57 的 8 个扫描另存为其它格式时会合并成一份点云，并多写一列 `scan`
  （站号，从 1 起）；再打开时按这一列**自动拆回多个扫描**，站结构不丢。
* e57 独有的 `<pose>`（多站位姿）只对 e57 有意义——其它格式读进来就是已经烘焙好的
  世界坐标，所以打开非 e57 时「应用 E57 位姿」会自动置灰。
* 文本格式坐标保留 3 位小数（单位 cm，约 10 µm 分辨率）；浮点一档的 PLY/PCD 坐标无损。
* **附加属性原样保留**：除坐标/颜色/强度/标注之外，文件里其余的顶点属性——法向
  `nx/ny/nz`、AgriTopo 的 `scale_0..2`、PCD 的 `ring/time` 等——会原样读进内存并
  原样写回，**连 dtype 都不降级**（`double` 仍是 `double`）。所以 PLY→PLY 往返不丢列、
  文件不会缩水；只有转存 e57 时这些列才会被丢掉（e57 的字段表是固定的，不塞私有字段）。
* 建议：长期归档仍用 **e57**（单文件、自带位姿与字段类型）；PLY / PCD 更适合交给
  CloudCompare、PCL 等外部工具继续处理。若原始数据带法向/scalar field 且后面还要用，
  归档时留一份 **e57 + 原始格式**双份，或者只对 e57 做标注、交付时再另存 PLY。
* **没有标注就不写 `label` / `instance`**：裁剪页只做几何裁剪、不产生标注，保存 PLY/PCD 时
  不会平白多出两列全 0 的标量场（CloudCompare 的字段列表里也就不会多出 label / instance），
  字段结构与源文件一致；一旦 `label>0` 或 `instance>0`，两列成对写回，语义不变。
* PLY 头**一律写 ASCII**（注释为英文），否则中文注释会被编码成 `?`，
  某些解析器直接拒绝打开。

> **旧版导出的标注 PLY 体积偏小？**（2026-11-16 之前）那时还不认未识别属性，标注后
> 只剩 `x y z rgb label instance`，每点 39 B 会掉到 22 B——丢的是 `nx/ny/nz`(12 B) 与
> `scale_0..2`(12 B)，点数和坐标没少，但法向和 scalar field 没了。留了原始 PLY 的话可以补回：
>
> ```bat
> python _merge_ply_extras.py "原始.ply" "标注_labeled.ply"
> ```
>
> 脚本按点序号把原始文件里的附加属性合到标注文件上（先校验点数与坐标一致），
> 输出 `*_labeled_full.ply` 并读回自检；之后用本软件打开再另存也不会再丢。

> **裁剪后另存成 e57，附加列还在吗？** 不在。e57 的字段表是固定的，裁剪页把带
> `nidar_views` / `nx,ny,nz` / `scale_*` 等私有列的 PLY 另存为 `.e57` 时，这些列会**整列丢失**；
> 而 `XYZ / RGB / intensity` 仍逐点无损（不缩放、不降精度、不做坐标变换）。
> 所以这类数据裁剪后应**另存为 `.ply`**，别选 `.e57`。已经存成 e57 的可以按坐标补回：
>
> ```bat
> python _restore_cropped_extras.py "原始.ply" "裁剪后.e57"
> ```
>
> 脚本用最近邻按坐标匹配（允许点数不同，要求只删点、不改坐标），输出 `*_full.ply`，
> 字段结构与原始 PLY 一致，并读回自检。与 `_merge_ply_extras.py` 的区别是后者要求
> 点数与点顺序完全一致。

标注在 e57 里写成两个整型字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `annotationLabel` | Integer 0–255（1 字节） | 0 未标注 / 1 穗 / 2 叶 / 3 茎 / 4 其他 |
| `annotationInstance` | Integer 0–65535（2 字节） | 实例编号，0 表示未归属 |

原始 `cartesianX/Y/Z`、`intensity`、`colorRed/Green/Blue`、`cartesianInvalidState`
均按位保留，已验证 358 万点 × 8 字段逐位一致。

**写入自检**：保存时按字段布局算出每段应写多少字节，写完立即比对实际写入量，
再检查文件长度；任何一处对不上就删掉半成品并报错，不会留下打不开的文件。
常见触发原因是某列长度与扫描点数不一致（例如标注数组被裁剪过）。

## 点云裁剪页

顶部选项卡切到「点云裁剪」即进入。这一页**不写标注**，只处理几何与文件。

### 布局

| 区域 | 内容 |
| --- | --- |
| 左侧 | 「文件列表」（打开文件夹、双击加载）与「配准裁剪」（脚本参数、运行日志）两个标签页 |
| 中间 | 三维视图 + 六个视角按钮 + 底部点数 / 包围盒信息 |
| 右侧 | 裁剪区域、绕轴旋转、显示（画布 / 着色 / 点大小）、保存四组 |

### 加载文件夹

点「打开文件夹…」递归收集 `.e57 / .ply / .pcd / .xyz / .txt / .csv / .pts`，
双击列表项载入；「刷新」重新扫描目录。点云1 / 点云2 下拉会自动预选列表里
唯一的 PLY / E57，并顺带推导出输出文件名。

### 画裁剪区域

1. 先选一个**视角**（俯视 / 前视 / 侧视 / 后视 / 底视 / 等轴）——
   区域是**当前屏幕投影**上的范围，换视角等于换裁剪方向。
2. 选形状（三个单选，默认「浏览」）：
   * **浏览（拖动旋转 / 平移）**：只看不画——左键拖动**旋转视角**，右键/中键拖动平移，
     滚轮缩放。右下角有 X/Y/Z 坐标轴指示器，转到哪个朝向一目了然
   * **矩形**：左键拖出，松开即确定
   * **任意多边形**：左键逐点点击，双击 / 右键 / `Enter` 闭合；
     `Backspace` 退一点，`Esc` 取消
3. 选保留方式：「只保留区域内的点」或「删除区域内、保留区域外」。
4. 选深度：默认**全部穿透**（沿视线方向全算）；「仅最前面一层」只动表面点。
5. 点「应用裁剪」。一次操作 = 一个撤销步，`Ctrl+Z` 可连续撤销；
   「重新载入」从磁盘重读、丢弃全部改动。

> **屏幕外点的归属**：视口之外的点永远算「区域外」。
> 所以「保留内」只留圈中且可见的部分，「保留外」会连同视口外的点一起保留——
> 两种方式点数严格互补（回归里有断言）。

**区域与视角的绑定**：区域是屏幕投影意义上的，所以在**画定那一刻**就把相机
（朝向 / 距离 / 中心）和视口尺寸一起锁定，之后旋转、缩放、平移或切换视角都
不会改变裁剪结果——状态栏会提示「区域已按画定时的视角锁定」。这样
「圈定时显示的命中 N 点」和「应用裁剪后实际删除的点」永远是同一批。
若开启了**旋转预览**（点的位置被挪动），已画的区域会自动清除并提示重新圈定；
切换深度模式也会立即刷新命中数标签。

> 多边形命中采用与 Qt 填充预览相同的 **偶奇（even-odd）规则**：圈内即命中，
> 凹多边形、自交套索同样成立。回归用 `QPainterPath.contains` 做独立参照逐点
> 比对，并验证「等价矩形与多边形掩膜完全一致」——曾因射线法初值写成
> `True` 导致内外完全颠倒，现已统一到 `renderer.point_in_polygon()`。

### 绕 X / Y / Z 任意角度旋转

三个数值框分别是绕 X / Y / Z 的角度（−360°～360°，可叠加，按 X→Y→Z 合成矩阵）。
默认绕点云包围盒中心旋转，取消勾选则绕坐标原点。

* **预览**：只改视图显示，文档坐标不动，拖数值实时更新
* **应用旋转**：把矩阵烘焙进每个点的 `cartesianX/Y/Z`（**不再改 E57 位姿**，
  因为读取时 pose 已经烘焙过），可 `Ctrl+Z` 撤销
* **复位**：角度归零并关闭预览，不撤回已应用的旋转

### 显示与着色

「显示」组里可选 **画布**（深色 / 浅灰 / 白色 / **自定义…**）与 **着色**

## 数据格式说明

* 写入使用自实现的 E57 编码器（1024 物理页 / 1020 载荷 + CRC32C 大端），无第三方依赖
* 读取优先 `pye57`（libE57），遇到自定义标注字段时自动切到内置解析器补读，
  因此**本软件保存的文件可以再次打开并继续编辑**
* 打开前会做一轮结构体检（头部长度、XML 段、每段起始/长度是否衔接），
  损坏文件直接给出中文原因，而不是画出垃圾点
* 其他软件（CloudCompare、ReCap 等）打开时能看到标准字段；`annotationLabel`
  属自定义字段，部分软件会忽略但不会报错

### 五个容易踩的 E57 细节

1. **四元数分量顺序是 (w, x, y, z)，单位元为 `w=1`**。
   把默认值写成 `(0,0,0,1)` 会被当作"绕 Z 轴 180°"，整份点云左右镜像、上下颠倒。
   `pye57` 的 `ScanHeader.rotation` 恰好是 `(x,y,z,w)`，直接拿来用会踩这个坑，
   因此一律从 XML 的 `<w><x><y><z>` 读取。
2. **XML 段可能不从页首开始**。本数据集 `xmlPhysicalOffset` 页内偏移 212，
   跨页时必须按"该页剩余载荷 + 后续整页 1020 字节"拼接，否则 CRC 字节会插进
   数值中间（如 `2.0N66765+01`），导致丢掉整个扫描。
3. **Integer 的声明区间决定存储宽度**。libE57 只看原型里的 `minimum`/`maximum`
   反推每点字节数，所以必须声明**该宽度的满量程**（1 字节 → `0..255`，
   2 字节 → `0..65535`），而不是实际值域。声明 1 字节却写 2 字节（早期
   `annotationInstance` 就是这样），CloudCompare 会报
   `unrecoverable inconsistent internal state`。
4. **段长与包链必须严丝合缝**。`fileOffset` 写在 XML 里、段长写在段头里，
   只要某段实写字节数与声明不同，后面所有段和 XML 的偏移都会错位，
   文件彻底打不开——这正是 2026-11-02 那份 `FS_09_labeled.e57` 失败的原因。
5. **两套偏移不能混用**。XML 里的 `fileOffset` 与段头里的"首包偏移"是**物理**
   偏移（含每页 4 字节 CRC），而内部按页拆包的工具函数收的是**逻辑**偏移。
   把物理值直接喂给逻辑函数，只有第一个扫描（偏移落在首页、两者相等）能读对，
   其余扫描的标注列会**静默丢失**——曾导致"多站文件重新打开后只剩第一站的标注"。

## 标注核查页与 Point-SAM（v2.1）

顶部切到「标注核查」。这页可以独立打开已标注/未标注点云，也可以点击
「载入器官标注页当前结果」复制其内存中的点云和标注（包含未保存修改）。
复制后各页独立编辑；核查完成请保存结果文件，再在需要的页面打开。

操作顺序：

1. 在核查列表选择扫描、器官实例或语义类别；已有目标以青色显示。
2. 大点云可先用「限定区域」框出局部；框选只限制本次推理，不会裁掉原始点。
3. 切「正点 +」点击目标，切「负点 −」点击误选背景或相邻器官。
4. 点击「运行 Point-SAM」，查看金色预览，并可切换模型返回的候选掩膜。
   「显示待应用预览」可临时关闭金色覆盖以对照原标注。
5. 指定穗/叶/茎/其他类别和实例方式，选择修正动作，再点击「应用当前选区」。
6. Ctrl+Z 撤销整步修正；Ctrl+S 另存核查结果；Ctrl+Shift+S 确认后覆盖保存。

修正动作：

- **补标未标注点**：默认操作，仅填补 label=0 的点，保护已有标注。
- **覆盖修正选区**：将金色选区重新分类，可只写语义类别、生成新实例或加入选中实例。
- **清除选区标注**：将选区的类别与实例编号清零。
- **替换当前实例边界**：先选中一个已有实例，将它的边界替换为预览掩膜；
  旧实例中落在新掩膜之外的点恢复为未标注。应用前会确认，可整步撤销。

加入/替换已有实例仅允许在该实例所属扫描内操作，避免跨站混淆实例编号。
也可用「将框选区域设为手动选区」直接补标或修正；它会明确显示为手动选区，
不会冒充模型结果。预测预览不修改标注，只有应用后的修改需要保存。
退出软件会检查所有三个页面，包括当前未显示的核查页。

### 本机 Point-SAM 配置

- 源码：`D:\PCProjects\01wheat\SemanticSegmentationofWheatOrgans\Point-SAM-main`
- Python：`D:\PCProjects\01wheat\Self-supervised\b2i_canopynet_v0.1.0\b2l\python.exe`

默认自动使用 CUDA，推理进程与 Qt 界面隔离，权重在首次运行时加载并驻留。
本机使用原仓库的 `PointCloudSAM.predict_masks(coords, features, prompt_coords,
prompt_labels, ...)`；未采用该仓库里与当前模型签名不一致的 Flask 演示。
Windows 下缺失 torkit3d 编译扩展时，使用 Torch 实现等价的 FPS/批量索引算子，
保留原模型和训练权重；使用原生 LayerNorm，不要求安装 Apex。

模型只预测「当前提示目标」的二值掩膜，**器官类别由用户指定**。
默认最多采样 10,000 点并强制包含提示点，再按最近邻将预测映射回限定区域的原始点。
可设置传播距离限制扩散。归一化、采样和颜色缩放仅发生在推理输入中；
保存仍使用原文档的坐标、颜色、属性和点顺序。
大范围稀疏采样可能遗漏细器官，宜缩小核查区域、补充正负点并人工检查边界。
模型分数是预测质量分数，不代表真实标注准确率。
